One bug, start to finish

A sample checkout bug, from the first error to the watched fix. Follow it in the graphical console or the terminal.

Same checkpoints. Your keyboard.

  1. 01 triage

    It notices, and decides it’s worth a fix

    Thirty-seven checkout errors share one fingerprint. Two small models triage them: real, not a duplicate, medium risk. A trail opens in git, and an agent starts on it.

  2. 02 checkpoint A

    Is this the right cause?

    The agent writes down what it thinks is wrong, and why. You read a page, not a diff. In checkout, policy says a person agrees before any code is written: press a.

  3. 03 evidence

    Ask why

    Press e to see what the hypothesis rests on: the error stream, the commit that started it, past trails, and the agent session that wrote that commit.

  4. 04 checkpoint A

    Or push back

    Press r and write a note. The agent gets it with the trail and tries again. Here, nothing is built until someone approves.

  5. 05 checkpoint B

    Reproduced, and a plan

    It reproduced the bug with a probe that fails on main, then planned the smallest fix. Comments stay on the trail, where the agent and the next reviewer see them.

  6. 06 checkpoint C

    Proof, before you look

    The fix arrives with its evidence. The probe passes now, so do 412 tests and six regression probes, replayed traffic shows nothing unexplained, and the diff is two files. Approving lands it.

  7. 07 landing

    It lands where you work

    This one lands as a Radicle patch. It could be a Tangled pull, a plain git ref or a live change in your devenv. Then it watches production for two hours.

  8. 08 watch

    It sets

    Two quiet hours later the trail closes. Its repro joins the regression probes, so this bug can’t come back unnoticed.

  9. 09 rollback

    Or it undoes itself

    A different fix, on a low-risk edge, landed without asking anyone. Twenty-seven minutes later a new error showed up in the file it touched, so Ephyra reverted it and reopened the trail.

You decide where it asks

One Markdown file in your repo says where a person decides, how a fix lands and how long it’s watched.

Checkout asks at A, B and C. Docs can land on their own once you enable that area. This example starts in shadow mode: every trail still waits for you.

Explore the pre-alpha

Ephyra is open source and pre-alpha. It is built to run on your own hardware or Railway, with no GitHub, and to land on Radicle, Tangled or plain git. The design explains how trails, checkpoints and landing work.
